# NOTES: работа с ассистентом

Работал с Claude Code. Схема: я формулирую решение и ограничения, Claude пишет код и тесты, я читаю каждый дифф и правлю
вручную

## Решения, принятые мной

| Решение                                                                            | Почему                                                                                                                                                                                     |
|------------------------------------------------------------------------------------|--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| Деньги в `int64` минорных единицах, произведение `profit × share` через `math/big` | Без `float` и без внешнего decimal; `big.Int` снимает переполнение на больших суммах. Верхняя граница `9·10^15` — ниже `Number.MAX_SAFE_INTEGER`, чтобы JSON безопасно читался в браузере. |
| Метод наибольших остатков, ничья по `investor_id`                                  | Сумма выплат всегда равна прибыли, результат детерминирован и не зависит от порядка вкладов. Смещение в пользу ранних ID ограничено одной копейкой — задокументировал в ARCHITECTURE.      |
| Агрегат `Problem` одним JSON-документом в SQLite                                   | Для среза — атомарность агрегата при минимальной схеме. Цена (нет SQL-отчётов по вкладам) записана в README.                                                                               |
| Transactional outbox вместо публикации из кода команды                             | Чтобы не было ни события без изменения, ни изменения без события; это же путь к брокеру без правки домена.                                                                                 |
| Ключ операции для вклада и распределения                                           | Повтор после таймаута не должен удваивать деньги.                                                                                                                                          |
| Фильтрация видимости по ролям на сервере                                           | UI не получает чужих данных вовсе, а не просто их не показывает.                                                                                                                           |
| Fiber v3, React/Vite                                                               | Удобство использования и опыт разработки на этих фреймворках                                                                                                                               |

## Что сгенерировал Claude

- Сервисный слой (`internal/services`) по моему описанию правил и матрицы ролей.
- Тесты движка, включая property-тест на сохранение суммы и независимость от порядка.
- `tests/api_test.go` (сценарий, гонки, матрица ролей, утечки) и `tests/happy_path.py`.
- Dockerfile, compose, CI.
- Черновики README, ARCHITECTURE и этого файла.

## Где правил руками

- Технолог, чьё решение не выбрано, видит форму «Предложить решение» на уже сматченной проблеме и получает 409: сервер
  скрывает от него матч целиком.
- Для `/profit` ключ операции обязателен, хотя распределение одно на пул; та же сумма с новым ключом даёт 409.
- Документы: переписал черновики

## Что предлагал Claude и я отклонил

- Kafka вместо in-process шины — для одного bounded context избыточно; путь к брокеру описан в ARCHITECTURE.
- Hyperledger Fabric / Solidity — вне рамок задания; движок написан так, чтобы переноситься в chaincode.
- JWT — для take-home достаточно заголовков с проверкой по сидам.
- ⟨другие предложения, если были⟩
