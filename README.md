# Инвест-пул региональной проблемы — Go API

Один bounded context цифровой экосистемы. Регион публикует проблему, технолог предлагает решение, эксперт подтверждает
матч, регион открывает инвестиционный пул, инвесторы вносят доли. Прибыль распределяется детерминированным движком
автоматически, без ручного одобрения выплаты.

Стек: Go 1.26, Fiber v3, SQLite (`modernc.org/sqlite`), transactional outbox и in-process шина.

Кабинет на React/Vite лежит в отдельном
репозитории: [invest-pool-react](https://github.com/phosphoriat/invest-pool-react).

Архитектура, контракт событий и правило округления описаны в [ARCHITECTURE.md](ARCHITECTURE.md). 
Работа с ассистентом описана в [NOTES.md](NOTES.md).

## Запуск

### Docker Compose (рекомендуется)

```sh
git clone https://github.com/phosphoriat/invest-pool-go.git
cd invest-pool-go
docker compose -p invest-pool up --build -d --wait
curl http://localhost:8080/health   # {"status":"ok"}
```

Имя проекта `-p invest-pool` важно: кабинет подключается к сети `invest-pool_default`. Данные SQLite хранятся в volume
`pool-data`. Полная очистка выполняется так: `docker compose -p invest-pool down -v`.

### Локально, без Docker

```sh
go run ./cmd
```

| Переменная      | По умолчанию     | Назначение         |
|-----------------|------------------|--------------------|
| `HTTP_ADDR`     | `:8080`          | Адрес HTTP-сервера |
| `DATABASE_PATH` | `invest-pool.db` | Файл SQLite        |

### Кабинет (UI)

После запуска API в соседнем каталоге выполните:

```sh
git clone https://github.com/phosphoriat/invest-pool-react.git
cd invest-pool-react
docker compose up --build -d --wait     # или: npm ci && npm run dev
```

Кабинет открывается на http://localhost:5173.

## Happy-path

### Одной командой (нужен Python 3, только стандартная библиотека)

```sh
python3 tests/happy_path.py
# другой адрес: BASE_URL=http://localhost:8081 python3 tests/happy_path.py
```

Скрипт создаёт новую проблему при каждом запуске, поэтому его можно повторять. Он проходит весь сценарий и попутно
проверяет отказы:

1. `region-tomsk` публикует «Томская область, очистка воды».
2. `tech-water` предлагает решение.
3. `expert-1` подтверждает матч. Повтор не создаёт второго события.
4. `region-tomsk` создаёт пул на `1000000`.
5. `investor-a` вносит `600000`, `investor-b` вносит `400000`. Каждый вклад отправляется дважды с тем же ключом, повтор
   не удваивает вклад.
6. `region-tomsk` фиксирует прибыль `100000`. Движок сам начисляет `60000` и `40000`. Повтор с тем же ключом ничего не
   меняет.
7. Каждый инвестор видит только своё начисление. Чужой регион не видит пул. В аудите ровно по одному `ProblemPublished`,
   `SolutionMatched`, `ProfitDistributed` и два `InvestmentAccepted`.

Попутно проверяются отказы: публикация не регионом, пул и вклад до матча, распределение до набора, вклад сверх цели,
подмена роли.

В конце скрипт печатает `PASS: happy-path, idempotency, roles, privacy, audit`.

### Через UI

Выберите пользователя в шапке кабинета и пройдите те же шаги: Томская область → Технолог очистки воды → Эксперт →
Томская область → Инвестор A → Инвестор B → Томская область. Кнопки «одобрить выплату» нет: начисления появляются сразу
после ввода прибыли.

## Роли и доступ

Аутентификация упрощённая и демонстрационная: заголовки `X-User-Id` и `X-Role`. Middleware сверяет пару с сидами.
Неизвестный пользователь получает `401`, роль, не совпадающая с сидом, получает `403`. Роль из заголовка без проверки по
сиду не принимается.

Сиды (`internal/models/user.go`, список отдаёт `GET /api/users`):

| ID             | Роль         | Имя                   |
|----------------|--------------|-----------------------|
| `region-tomsk` | region       | Томская область       |
| `region-other` | region       | Другой регион         |
| `tech-water`   | technologist | Технолог очистки воды |
| `tech-other`   | technologist | Другой технолог       |
| `expert-1`     | expert       | Эксперт               |
| `investor-a`   | investor     | Инвестор A            |
| `investor-b`   | investor     | Инвестор B            |
| `investor-c`   | investor     | Инвестор C            |

### Матрица прав (реализована на API)

| Действие                                                        | region                 | technologist                                                                             | expert | investor                                                  |
|-----------------------------------------------------------------|------------------------|------------------------------------------------------------------------------------------|--------|-----------------------------------------------------------|
| Публиковать проблему                                            | да                     | нет                                                                                      | нет    | нет                                                       |
| Предложить решение                                              | нет                    | да                                                                                       | нет    | нет                                                       |
| Подтвердить матч                                                | нет                    | нет                                                                                      | да     | нет                                                       |
| Создать пул (после матча)                                       | да, только свой регион | нет                                                                                      | нет    | нет                                                       |
| Внести долю                                                     | нет                    | нет                                                                                      | нет    | да                                                        |
| Зафиксировать прибыль (распределение запускается автоматически) | да, только свой регион | нет                                                                                      | нет    | нет                                                       |
| Смотреть состояние (`GET /api/state`)                           | свои проблемы целиком  | все проблемы, только свои решения; пул без инвесторов и выплат, если выбрано его решение | всё    | открытые пулы (каталог) + только свои вклады и начисления |
| Журнал аудита (`GET /api/events`)                               | события своих проблем  | нет                                                                                      | все    | нет                                                       |

Фильтрация выполняется на сервере в `PoolsService.View`. Клиент получает только разрешённые данные: read-модель
`models.ProblemView`, а не сам агрегат. Ключи операций в неё не попадают. Поле `matched` показывает, что эксперт уже
подтвердил матч. Технолог, чьё решение не выбрано, видит `matched: true` без `match` и пула. Так UI не предлагает ему
отправить решение в закрытую проблему, и при этом не раскрывает, чьё решение выбрано.

## API

Все ответы в формате JSON. Ошибки возвращаются как `{"error": "..."}`. Тело запроса — один JSON-объект до 16 КБ,
неизвестные поля отклоняются.

| Метод и путь                         | Роль              | Тело               | Успех                                       |
|--------------------------------------|-------------------|--------------------|---------------------------------------------|
| `GET /health`                        | —                 | —                  | `{"status":"ok"}`                           |
| `GET /api/users`                     | —                 | —                  | список сидов                                |
| `GET /api/state`                     | любая             | —                  | `{"projects":[...], "opportunities":[...]}` |
| `GET /api/events`                    | region, expert    | —                  | события аудита                              |
| `POST /api/problems`                 | region            | `{"text"}`         | `{"problem_id"}`                            |
| `POST /api/problems/:id/solutions`   | technologist      | `{"text"}`         | `{"problem_id"}`                            |
| `POST /api/problems/:id/match`       | expert            | `{"solution_id"}`  | `{"problem_id"}`                            |
| `POST /api/problems/:id/pool`        | region (владелец) | `{"amount"}`       | `{"problem_id"}`                            |
| `POST /api/problems/:id/investments` | investor          | `{"amount","key"}` | `{"problem_id"}`                            |
| `POST /api/problems/:id/profit`      | region (владелец) | `{"amount","key"}` | `{"problem_id"}`                            |

Пример запроса:

```sh
curl -X POST http://localhost:8080/api/problems \
  -H 'X-User-Id: region-tomsk' -H 'X-Role: region' \
  -H 'Content-Type: application/json' \
  -d '{"text":"Томская область, очистка воды"}'
```

### Деньги

Все суммы — целые минорные единицы (`int64`, например копейки). Допустимый диапазон: `1…9 000 000 000 000 000`. Верхняя
граница ниже `Number.MAX_SAFE_INTEGER`, поэтому JSON безопасно читается в браузере. `float` нигде не используется.
Произведение `прибыль × доля` считается через `math/big`.

### Коды ответа

| Код   | Когда                                                                                                                                                                                |
|-------|--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| `400` | некорректный JSON, лишние поля, нет ID                                                                                                                                               |
| `401` | неизвестный `X-User-Id`                                                                                                                                                              |
| `403` | роль не совпадает с сидом, действие не разрешено роли, чужой регион                                                                                                                  |
| `404` | проблема не найдена                                                                                                                                                                  |
| `409` | нарушение состояния: нет матча или пула, матч уже выбран, пул уже создан, набор закрыт, вклад сверх остатка, пул не набран, прибыль уже зафиксирована, ключ повторён с другой суммой |
| `422` | невалидные данные: сумма вне диапазона, нет ключа операции, длина текста, решение не принадлежит проблеме                                                                            |

### Идемпотентность команд

| Команда                                   | Правило                                                                                                                                                                                      |
|-------------------------------------------|----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| Подтвердить матч                          | Повтор с тем же `solution_id` возвращает `200` без изменений и без события. Другое решение возвращает `409`.                                                                                 |
| Внести долю                               | Дедупликация по паре (инвестор, `key`) внутри пула. Тот же ключ и та же сумма возвращают `200` без изменений. Тот же ключ с другой суммой возвращает `409`. Новый ключ означает новый вклад. |
| Зафиксировать прибыль                     | Тот же `key` и та же сумма возвращают `200` без изменений. Любая другая комбинация после распределения возвращает `409`.                                                                     |
| Публикация проблемы и предложение решения | Не идемпотентны: каждый вызов создаёт новую сущность.                                                                                                                                        |

Ключ операции занимает от 1 до 128 байт. Клиент генерирует его заранее и повторяет при неизвестном результате, например
после таймаута.

## Структура

```
cmd/main.go                  запуск, graceful shutdown, фоновая доставка outbox
internal/handlers            HTTP: разбор запроса → сервис → JSON
internal/middleware          аутентификация, валидация
internal/services            сервисы и бизнес-логика
internal/repository          слой данных
internal/models              сущности и сиды
internal/validation          правила валидации
migrations                   схема БД
tests                        unit и интеграционные тесты
```

## Что отрезано и почему

Это осознанные упрощения среза на 3–4 часа. Подробнее о том, как их снять, — в [ARCHITECTURE.md](ARCHITECTURE.md).

- **Одно распределение на пул.** Пилот фиксирует прибыль один раз. Повторные периоды прибыли (`[]Distribution` с ключом
  периода) не реализованы.
- **Один инстанс.** Целостность агрегата держится на mutex репозитория и одном соединении с SQLite. Горизонтальное
  масштабирование потребует Postgres и оптимистичной блокировки.
- **Агрегат хранится JSON-документом.** Вклады и выплаты не вынесены в отдельные таблицы, поэтому кросс-пуловые отчёты
  не построить SQL-запросом.
- **Демо-аутентификация.** Заголовки вместо токенов. Сиды захардкожены.
- **Начисления, а не переводы.** Движок фиксирует, кому сколько причитается. Платёжного контура нет.
- **Outbox упрощён.** Доставленные записи не удаляются. Ошибка подписчика на одном событии задерживает следующие до
  повтора (head-of-line). В конверте события нет версии схемы.
- **Ключи идемпотентности видны региону и эксперту** в составе вкладов. Для демо это допустимо, в бою их стоит вырезать
  из представления.
